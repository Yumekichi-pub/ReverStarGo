# おでかけ告知キット

旅行や帰省で発送をお休みするあいだ、サイトに「**注文は受け付けています。発送だけお休みします**」
という告知を出すための、使い回せる仕組みです。

いちばん大事なところだけ先に書きます。

| したいこと | やること |
|---|---|
| **お出かけモードにする** | `odekake.js` の `on: false` を `on: true` に変えて、日付を入れる |
| **通常モードに戻す** | `odekake.js` の `on: true` を `on: false` に戻す |
| **戻し忘れたとき** | `until` の日の朝0時に、ひとりでに消えます |

書き換えるファイルは `odekake.js` の **1つだけ**です。
HTMLもCSSも、お出かけのたびに触る必要はありません。

---

## 1. さいしょの一回だけ：サイトへの取り付け

ここは初回のみの作業です。一度やっておけば、次からは 2. の手順だけで済みます。

### 1-1. ファイルを置く

`odekake.css` と `odekake.js` を、サイトの中に置きます。
（`css/` や `js/` フォルダがあればそこへ。無ければサイトのいちばん上でも構いません）

### 1-2. 各ページに 2行ずつ足す

告知を出したいページの `<head>` の中に：

```html
<link rel="stylesheet" href="/odekake.css">
```

`</body>` のすぐ上に：

```html
<script src="/odekake.js"></script>
```

共通ヘッダー・共通フッターを読み込むつくりなら、その共通パーツに1回書けば全ページに入ります。
**この2行は、通常モードのあいだ何も表示しません。** 入れっぱなしにしておいてください。

### 1-3. 告知を出したい場所に「置き場所」を作る

告知そのものは書きません。空っぽの印を置くだけです。

| 書くもの | 何が出るか | どこに置くか |
|---|---|---|
| `<div data-odekake="bar"></div>` | 大きめの告知バー | トップページのヘッダー直後（見出しより上）／ショップへのボタンの直前 |
| `<div data-odekake="note"></div>` | 小さな注記（※〜） | 「ご購入の流れ」の「商品の発送」の項目のすぐ下 |
| `<span data-odekake="legal"></span>` | 法定表記に足す一文 | 特定商取引法ページの「商品の引渡し時期」の欄の中 |

同じ印を1ページに何個置いても大丈夫です（昔ながらの `id` と違い、重複しても壊れません）。

すぐ下にショップのボタンがある場所など、告知の中のリンクが二重になって野暮なときは、
`data-odekake-nolink` を足すと、その置き場所だけリンクを省きます。

```html
<div data-odekake="bar" data-odekake-nolink></div>
```

**置き場所の目安**：お客様が注文にたどり着くまでに必ず通るところ。
とくに **購入ボタンの直前** は、最後の接点なので必ず入れてください。

### 1-4. 見た目を合わせる

`odekake.css` のいちばん上にある変数だけ、サイトの雰囲気に合わせて変えてください。

| 変数 | 何の色・大きさか |
|---|---|
| `--odekake-bg` | 告知バーの地の色 |
| `--odekake-border` | ふちの色 |
| `--odekake-accent` | 左端の太い線。ふちと同じ色にすれば目立たなくなる |
| `--odekake-text` | 文字の色 |
| `--odekake-link` | リンクと注記の色 |
| `--odekake-radius` | 角のまるさ |
| `--odekake-font-size` | 文字の大きさ |
| `--odekake-width` | 横幅のいちばん広いところ |

派手にしないこと。目立たせたいのはメッセージであって、飾りではありません。

サイトによっては、これだけでは足りないことがあります。たとえば画面の上に貼りつく
（`position: fixed` の）ヘッダーがあるサイトでは、告知バーがヘッダーの下に潜り込みます。
そういう「そのサイト特有の事情」は、`odekake.css` のいちばん下の
**「サイトごとの調整」**の欄に書いてください。告知が出ていないときは効かないように、
`[data-odekake="bar"]:not(:empty)` から書き始めるのがこつです。

## 2. お出かけのたびの手順

`odekake.js` の上のほうにある、この四角の中だけ書き換えます。

```js
var CONFIG = {
  on: true,                 // ← お出かけ中は true
  from:  '2026-09-13',      // 発送をお休みする最初の日
  until: '2026-10-01',      // 発送を再開する日（この日の朝0時に告知が消えます）
  shopUrl: 'https://yumekichi-publishing.stores.jp/',
  shopLabel: 'オンラインショップはこちら',
  pdfAvailable: true,       // PDFは期間中も買える？
  replyDelay: true,         // お返事も遅れる？
  heading: 'ご注文は通常どおり承っています（発送のみお休みします）'
};
```

日付は `YYYY-MM-DD` の形で書きます。**曜日は書きません。**
「9月13日（日）」「9月30日（水）」「10月1日（木）」といった曜日つきの文は、
入れた日付から自動で作られます。曜日を間違える心配はありません。

`until` に入れるのは、**お休みの最終日ではなく、再開する日**です。
9月30日までお休みなら `until: '2026-10-01'` と書きます。
告知には自動で「9月13日（日）〜9月30日（水）」と出ます。

### 保存しただけでは、まだ公開されていません

ここでつまずきやすいので、はっきり書いておきます。

同じファイルが2か所にあります。**手元の作業用のコピー**と、
**サーバーにあってお客様が実際に見ているファイル**です。
メモ帳で書き換えて保存しても、直っているのは手元のほうだけです。

```
手元を直す  →  サーバーにアップロードする  →  はじめて公開される
                        ↑
              これを忘れると、何も変わりません
```

逆に、サーバー側だけを直して手元を忘れると、次に手元から何かを
アップロードしたときに、変更が元に戻ってしまいます。両方そろえてください。

アップロードするのは **`odekake.js` の1つだけ**です。HTMLは触りません。
アップロードしたあと、ブラウザで **Ctrl + F5**（強制再読み込み）して確認します。
画面が古いままなら、ブラウザが前の内容を覚えているだけです。

取り付け先によっては、アップロードしたファイルの**権限（パーミッション）**が
正しく付いているかも見てください。ほかのページと同じ `rw- r-- r--`（644）に
なっていれば正常です。ここが外れているとサーバーがファイルを読めず、
403エラーになります。

---

## 3. 帰ってきたら：通常モードに戻す

```js
  on: false,
```

これだけです。日付はそのまま残して構いません。次のお出かけのとき、上書きすればよいので。

`until` の日を過ぎていれば、`on: true` のままでも告知は表示されません。
**戻し忘れても、お客様に古い告知が見えることはありません。**
ただ、次のお出かけのときに混乱しないよう、帰ったら `false` に戻しておくのがおすすめです。

## 4. 出す前のたしかめ

サイトにアップロードする前に、ブラウザで確認できます。

- 見え方をたしかめる → URL の末尾に `?odekake-preview=1` を付けて開く
  （`on` が `false` のままでも、その場で表示されます。自分のブラウザの中だけの話です）
- 消えるかたしかめる → URL の末尾に `?odekake-now=2026-10-02` を付けて開く
  （10月2日にお客様が開いたことにして表示します。何も出なければ正解）

見本ページ `demo.html` を開けば、4か所すべての見え方をまとめて確かめられます。

**チェックリスト**

- [ ] スマートフォンの幅（375pxくらい）で、文字が詰まらず読めるか
- [ ] 告知の中のリンクが、ちゃんとショップに飛ぶか
- [ ] ヘッダー・ヒーロー・フッターのレイアウトが崩れていないか
- [ ] 日付と曜日が合っているか（自動生成されますが、`from` と `until` の入力自体は目で確認）
- [ ] `?odekake-now=` で再開日の翌日にしたとき、告知が消えるか

## 5. やってはいけないこと

- **商品を非公開にしない。売り切れ表示に変えない。** 受付は続いています。
- **サイト全体のデザインを変えない。** 告知は控えめに、既存の配色に馴染ませる。
- **法定表記（特定商取引法のページ）の既存の文言は書き換えない。** 足すだけ。

「発送休止」という言葉だけを見て「買えないんだ」と離れてしまうお客様が出ないよう、
見出しでは先に「**注文は受け付けています**」と伝えるようにしてあります。

### 法定表記について、ひとつだけ

`data-odekake="legal"` の一文は JavaScript で表示されます。
JavaScript を切っているお客様には見えません。もとの引渡し時期の記述は静的なHTMLのまま残るので
表記が欠けることはありませんが、念のため確実に出したい場合は、
その一文だけ手でHTMLに直接書き足し、帰ってきたときに消してください。

## 6. サイトの編集ではない、手作業のぶん

以下はサイトのファイルではないので、この仕組みの外です。お出かけのたびに手で行ってください。

1. **STORESショップ**
   - ストア紹介文のいちばん上に告知
   - 発送をともなう各商品ページの説明文の冒頭に告知
   - 注文完了時の自動返信メールに一文追加
2. **LINE公式アカウント**
   - 一斉配信で告知（お返事が遅れることも添える）
3. **在庫数の確認**
   - 受付を続けるので、出発前に実在庫と登録数を突き合わせる
4. **カレンダーへの登録**
   - 再開日に「通常モードに戻す」の予定を入れておく

## 7. 中身の説明（気になったときだけ）

| ファイル | 役割 |
|---|---|
| `odekake.js` | 設定と、告知を組み立てて置き場所に入れる処理 |
| `odekake.css` | 告知の見た目。色は上の変数でまとめて変えられる |
| `demo.html` | 見え方をたしかめる見本ページ（サイトには不要） |
| `README.md` | この手引き |

告知が出ていないあいだ、置き場所の `<div>` は `[data-odekake]:empty { display: none; }`
によって完全に無いものとして扱われます。余白も線も残りません。
