# スタポジ検証用 MT4 スクリプト（楽天MT4・デモ口座）

「スタポジ」EA化の前段階として、**楽天MT4のデモ口座で保留注文をどこまで積めるか**を
実測するためのスクリプト2本です。

| ファイル | 役割 |
|---|---|
| `StackTest.mq4` | Buy Stop の保留注文を連続発注し、何本目で失敗するか・エラーコード・所要時間を記録 |
| `CleanUp.mq4`   | テストで出した保留注文を一括削除 |

> ⚠️ **デモ口座専用のつもりで作っています。** リアル口座で走らせないでください。
> `StackTest.mq4` はリアル口座を検知すると警告を出しますが、止めはしません。

---

## 1. ファイルの置き場所

このリポジトリはクラウド上のLinuxコンテナで動いているので、**お使いのWindows 11 PCの
MT4データフォルダに直接置くことはできません**。下の手順でコピーしてください。

1. MT4を起動
2. メニュー **ファイル → データフォルダを開く**（File → Open Data Folder）
   - 通常は `C:\Users\<ユーザー名>\AppData\Roaming\MetaQuotes\Terminal\<32桁の英数字>\`
   - 楽天MT4は独自インストーラなので `AppData\Roaming\Rakuten...` 配下のこともあります。
     どちらでも「データフォルダを開く」で開いた場所が正解です。
3. 開いたフォルダの中の **`MQL4\Scripts\`** に `StackTest.mq4` と `CleanUp.mq4` をコピー
4. MT4の「ナビゲータ」ウィンドウで **スクリプト** を右クリック → **更新**（Refresh）
   - 一覧に出てこない場合は、MetaEditorで開いて **コンパイル（F7）** してください。
     `MQL4\Scripts\` に `.ex4` ができれば成功です。

---

## 2. MT4側の設定（自動売買の許可）

スクリプトから発注するには、以下が**すべて**必要です。

1. **ツール → オプション → エキスパートアドバイザ** タブ
   - ☑ 自動売買を許可する（Allow automated trading）
   - ☑ 「外部エキスパートの無効化を...」系のチェックは外れていてOK
   - DLL/WebRequestの許可は**不要**です（このスクリプトは使いません）
2. ツールバーの **「自動売買」ボタンを ON**（緑の再生マーク。赤い■だとOFF）
3. スクリプトをチャートにドラッグしたときのダイアログで
   **「自動売買を許可する」にチェック**を入れてから OK
   - ここのチェックを忘れるとエラー **4109（trading is not allowed）** で全滅します
4. チャート右上に **ニコちゃんマーク😊** が出ていれば実行可能な状態です
   （×マークだと動きません）

## 3. 使い方

### StackTest.mq4

USDJPYのチャートを開いて、ナビゲータから `StackTest` をチャートにドラッグ＆ドロップ。
パラメータ画面が出ます。

| パラメータ | 既定値 | 意味 |
|---|---|---|
| `VolumeUnits` | `1000` | **通貨量**での発注サイズ。1,000通貨 = 0.01ロット |
| `MaxLotsGuard` | `0.10` | 1本あたりのロット上限（誤操作防止の安全弁）。超えると起動時に中断 |
| `StartPrice` | `0.0` | 発注開始価格。`0` なら「現在Ask + StartOffsetYen」を自動採用 |
| `StartOffsetYen` | `0.50` | 上記が0のときのオフセット（円） |
| `StepPips` | `20.0` | 注文間隔（pips）。`0.1` まで下げられます |
| `MaxOrders` | `500` | 試行する最大本数 |
| `SleepMs` | `100` | 1本ごとの待機ミリ秒。エラー8/141が出たら増やす |
| `StopAfterFails` | `20` | 連続失敗がこの回数に達したら打ち切り（`0`で無制限に続行） |
| `MagicNumber` | `20260831` | 注文タグ。`CleanUp.mq4` の絞り込みに使います |
| `WriteCsvLog` | `true` | 結果を `MQL4\Files\` にCSV出力 |

**ロット単位について（重要）**

ご指定は「通貨量で指定して内部で100で割る」でしたが、MT4の1.00ロット＝10万通貨なので
正しくは **÷100,000** です。÷100だと 1,000通貨 → 10.00ロット（＝100万通貨）になって
しまうため、`VolumeUnits / 100000.0` で実装しました。
加えて `MaxLotsGuard`（既定0.10ロット）を超えると**発注前に中断**します。
念のため最初は `VolumeUnits=1000`（＝0.01ロット）のまま走らせてください。

**エラー時の挙動**

- 失敗しても即中断せず、エラーコードを記録して次の価格へ進みます
- 最後にエラーコード別の集計（コード / 回数 / 最初に出た本数 / 意味）を出します
  - 一時的なエラー（4, 128, 135, 136, 137, 138, 146…）が散発 → サーバー側の混雑
  - 恒久的な上限（**148 = too many orders**, 134 = 証拠金不足, 131 = ロット不正）が
    その本数以降ずっと続く → そこが業者側の壁
- 連続で `StopAfterFails` 回（既定20）失敗したら打ち切り。壁を確認したあと
  480本ぶんエラーを出し続けても意味がないためです。壁の先も全部試したい場合は `0` に

**出力**

- Expertsタブ（＝`Print()` の出力先。両方に出す、は同じ場所になります）
- チャート左上に `Comment()` でサマリー
- `MQL4\Files\StackTest_USDJPY_YYYYMMDD_xxxx.csv`（`WriteCsvLog=true` のとき）

起動時には環境情報も出します（StopLevel / FreezeLevel / MinLot / MaxLot / LotStep /
スプレッド / 余剰証拠金）。「現在価格から0ポイント圏内〜」の表示どおり
StopLevelが0なら、ログにも `StopLevel=0.0pt` と出るはずです。

### CleanUp.mq4

同じくチャートにドラッグ＆ドロップ。

| パラメータ | 既定値 | 意味 |
|---|---|---|
| `OnlyThisSymbol` | `true` | チャートの通貨ペアのみ対象 |
| `MagicNumber` | `20260831` | この番号の注文だけ削除。`-1` で全部 |
| `MaxPasses` | `20` | 削除の巡回回数（数千本でも消えるように） |
| `SleepMs` | `50` | 1本ごとの待機 |
| `RetryPerOrder` | `3` | 1注文あたりのリトライ回数 |

**保有ポジション（OP_BUY / OP_SELL）は絶対に触りません。**
消すのは保留注文（Stop / Limit）だけです。

## 4. おすすめの検証手順

1. `MaxOrders=20`, `StepPips=20` で試運転 → 20本すべて成功するか、ログの見え方を確認
2. `CleanUp` で全消し
3. `MaxOrders=500`, `StepPips=20` で本番計測 → 壁の本数とエラーコードを記録
4. `CleanUp` で全消し
5. `StepPips=1`（間隔を詰める）でもう一度 → 「本数の上限」なのか
   「価格帯の制約」なのかを切り分け
6. 壁が **148（too many orders）** なら業者の注文数上限、
   **134（not enough money）** なら証拠金の壁 ＝ ロットか価格帯の調整で伸ばせます

`SleepMs` は最初100msで。所要時間が問題になったら 50 → 20 と下げて、
エラー8 / 141 / 146 が出始めるところが投げる速度の限界です。

---

## 5. 既知の注意点

- スクリプトは**1チャートに1本**しか動きません（実行中に別のスクリプトを落とすと前のが止まります）
- 500本×100msで**最低50秒**かかります。終わるまでMT4を触らないでください
- 週末や市場クローズ中はエラー132（market is closed）で全滅します。平日の取引時間に
- チャートを閉じる／時間足を変えるとスクリプトは強制終了します
- ソースのコメント・ログは意図的に英語（ASCII）です。MetaEditorの文字コードの都合で
  日本語コメントが文字化けすることがあるためです
